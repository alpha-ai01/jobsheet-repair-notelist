# Jobsheet Data Model (Canonical)

The new system uses a flat Firestore structure: `/jobsheets/{jobId}`.

## JobSheet
- `id` (string, document ID)
- `jobNumber` (string)
- `customerName` (string)
- `customerPhone` (string)
- `deviceType` (string)
- `brand` (string)
- `model` (string)
- `serialNumber` (string)
- `imei` (string)
- `problem` (string)
- `technicianNote` (string)
- `repairNote` (string)
- `estimatedPrice` (number)
- `finalPrice` (number)
- `deposit` (number)
- `status` (string, enum: received, checking, waiting_parts, repairing, completed, delivered, cancelled)
- `createdAt` (timestamp)
- `updatedAt` (timestamp)
- `completedAt` (timestamp)
- `archivedAt` (timestamp)
- `createdBy` (string, user ID)
- `updatedBy` (string, user ID)

## Status History (Subcollection: /jobsheets/{jobId}/statusHistory/{historyId})
- `fromStatus` (string)
- `toStatus` (string)
- `changedBy` (string, user ID)
- `changedAt` (timestamp)
- `note` (string)
